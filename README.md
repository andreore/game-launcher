# Лаунчер

Собирает в одном окне игры и запускает их одной
кнопкой. Написан на Rust с оболочкой Tauri, интерфейс на HTML и CSS
с TypeScript.

Rust выбран не ради скорости. Лаунчер почти ничего не считает: читает папку,
показывает список, запускает процесс. Взамен он даёт один компактный
исполняемый файл и нормальную работу с процессами. Игра стартует отдельно от
лаунчера и продолжает работать, если лаунчер закрыть.

## Как устроено

Логика отделена от окна. Крейт `crates/launcher-core` собирается и тестируется
без графических библиотек, поэтому тесты идут даже там, где окно собрать нечем.

Устроено это просто. Ядро умеет читать папку игр, разбирать манифест, находить
обложку, хранить настройки и запускать процесс. Окно в `src-tauri` ничего из
этого не повторяет: оно выставляет наружу команды для страницы, а страница
в `src` их вызывает и рисует то, что пришло.

```
game-launcher/
├─ crates/launcher-core/     ← вся логика лаунчера
│  ├─ src/manifest.rs          формат game.json и его проверка
│  ├─ src/library.rs           обход папки игр, размер, поиск обложки
│  ├─ src/launch.rs            запуск игры отдельным процессом
│  ├─ src/cover.rs             обложка игры для интерфейса
│  ├─ src/news.rs              новости лаунчера из news.json
│  ├─ src/settings.rs          тема и поведение между запусками
│  ├─ src/catalog.rs           список игр, которые можно скачать
│  ├─ src/install.rs           скачивание и распаковка архива
│  ├─ src/open.rs              открыть папку в файловом менеджере
│  └─ tests/                   тесты: 44 штуки, на настоящих файлах
├─ src-tauri/                ← окно: только связывает ядро с интерфейсом
│  └─ src/lib.rs               команды для веб-страницы
├─ src/                      ← интерфейс
│  ├─ main.ts                  логика: выбор, поиск, запуск, настройки
│  ├─ view.ts                  разметка: панель игр, игра, новости
│  ├─ api.ts                   данные и режим предпросмотра
│  └─ styles.css               оформление
├─ games/                    ← САМИ ИГРЫ: одна папка на игру
│  └─ README.md                формат описания игры, с примером
├─ catalog.example.json      ← пример списка игр для скачивания
├─ news.json                 ← новости лаунчера (создаётся вручную)
├─ settings.json             ← тема и поведение (создаётся сам)
└─ Cargo.toml                  рабочее пространство из двух крейтов
```

### Что где в окне

Раскладка повторяет лаунчер Minecraft: слева тёмная панель, справа светлая
область. Сверху две вкладки: «Мои игры» и «Каталог».

Слева сверху заглушка аккаунта: аккаунты появятся позже, пока там написано
«не выбран».

Под ней список игр с названием и версией. Выбранная отмечена зелёной полосой
слева. Стрелки вверх и вниз ходят по списку, Enter запускает игру, поиск в
верхней строке фильтрует список. Рядом с надписью «Игры» стоит кнопка «+»: она
создаёт папку новой игры с заготовкой `game.json` и сразу открывает её.

Справа панель выбранной игры: обложка, название, версия, автор, размер, теги,
описание и кнопки «Играть», «Папка игры» и «Удалить». Удаление спрашивает
подтверждение и показывает путь к папке, которая исчезнет. Ниже новости
лаунчера из `news.json`.

Слева внизу кнопка настроек. Внутри тема оформления, закрытие лаунчера при
запуске игры, путь к папке игр и версия лаунчера.

### news.json

Файл лежит рядом с папкой игр, в режиме разработки в корне проекта. Формат
простой, массив объектов:

```json
[
  {
    "title": "Добавили «Танчики»",
    "text": "Пять уровней и режим на двоих за одной клавиатурой.",
    "date": "5 ноября"
  }
]
```

`text` и `date` можно не писать. Показываются первые двенадцать новостей.
Если файла нет, на его месте будет подсказка, куда его положить.

## Что нужно установить

Rust ставится через [rustup](https://rustup.rs). Именно rustup: вместе с ним
приходят `cargo fmt` и `cargo clippy`, которые пригодятся при правках. Node.js
нужен версии 20 или новее: [nodejs.org](https://nodejs.org).

Для окна на Fedora требуются системные библиотеки:

```bash
sudo dnf install webkit2gtk4.1-devel gtk3-devel libsoup3-devel \
                 openssl-devel librsvg2-devel
```

Без них соберётся и пройдёт тестами только ядро. Окно не соберётся.

## Запуск и сборка

```bash
npm install
npm run tauri dev
```

Окно откроется само, а правки в интерфейсе будут видны сразу, без перезапуска:
это горячая перезагрузка. Готовый лаунчер для друзей собирается командой
`npm run tauri build`. Файл появится в `src-tauri/target/release`.

## Как выпустить новую версию

Сборку делают машины GitHub, самому собирать ничего не нужно.

1. Поднимите номер версии в `src-tauri/tauri.conf.json`. Его берут и сборка, и
   файл обновлений.
2. Поставьте тег с тем же номером и отправьте:

   ```bash
   git tag v0.2.0
   git push origin v0.2.0
   ```

3. Дальше всё само: GitHub соберёт сборки для Windows и Linux, приложит файлы к
   релизу и положит рядом `latest.json` со ссылками и подписями. Минут через
   десять релиз готов, а установленные лаунчеры увидят новую версию и предложат
   обновиться.

Сборка подписывается ключом из секретов репозитория
(`TAURI_SIGNING_PRIVATE_KEY`). Без него шаг обновлений не пройдёт, поэтому
секрет лучше не удалять.

## Каталог игр

Вкладка «Каталог» показывает игры, которые можно скачать. Список лежит не
внутри лаунчера, а на сервере: проще всего держать его на GitHub. Тогда все,
кто скачал лаунчер, видят один и тот же список и качают игры оттуда же.

Что нужно сделать один раз:

1. Создать публичный репозиторий на GitHub.
2. Положить в него файл `catalog.json` со списком игр. Пример лежит рядом:
   [`catalog.example.json`](catalog.example.json).
3. Собрать каждую игру в zip-архив, приложить архивы к релизу
   (Releases → Draft a new release), а в `catalog.json` прописать прямые ссылки
   вида `https://github.com/ЛОГИН/РЕПОЗИТОРИЙ/releases/download/МЕТКА/игра.zip`.
4. Открыть в лаунчере настройки, вставить в поле «Каталог игр» ссылку на
   `catalog.json` и нажать «Проверить и обновить». Ссылка на сырой файл
   выглядит так:
   `https://raw.githubusercontent.com/ЛОГИН/РЕПОЗИТОРИЙ/main/catalog.json`.

Дальше список один на всех: правите `catalog.json` в репозитории, и игры
появляются у всех, у кого стоит лаунчер. Если сети нет, лаунчер показывает
последний сохранённый список и говорит об этом.

### Формат catalog.json

```json
{
  "games": [
    {
      "id": "snake",
      "title": "Змейка",
      "version": "0.3.0",
      "author": "мы с друзьями",
      "description": "Классика про растущую змею.",
      "size": 48200000,
      "cover": "https://example.com/snake.png",
      "url": "https://github.com/ЛОГИН/РЕПОЗИТОРИЙ/releases/download/v1/snake.zip"
    }
  ]
}
```

Обязательных полей три: `id`, `title` и `url`. Всё остальное можно не писать.
`id` превращается в имя папки внутри `games/`, поэтому в нём допустимы только
латинские буквы, цифры, точка, дефис и подчёркивание. `size` показывается на
карточке до скачивания, `cover` подтягивается по ссылке. Записи, где чего-то из
обязательных полей нет, лаунчер молча пропускает: одна опечатка не сломает
весь список.

### Что должно быть в архиве

`game.json` в корне архива, рядом с файлами игры. Собирайте архив из содержимого
папки игры, а не из самой папки. Если всё-таки заархивировать папку целиком,
лаунчер поднимет файлы на уровень выше сам, но лучше так не делать.

Если игра с таким `id` уже стоит, на карточке написано «Уже стоит», и скачать
её второй раз нельзя. Чтобы обновить игру, удалите старую и скачайте заново.

## Обновление лаунчера

Лаунчер умеет обновлять сам себя.

В настройках есть галочка «Проверять обновления лаунчера при запуске» и кнопка
«Проверить обновление». Лаунчер читает файл `latest.json`, который лежит рядом с
`catalog.json` в том же репозитории. Адрес выводится из адреса каталога: если
каталог это `https://raw.githubusercontent.com/ЛОГИН/РЕПО/main/catalog.json`, то
описание версии ищется в `.../main/latest.json`. Отдельно настраивать нечего.

Сборку релиза нужно подписывать, иначе лаунчер обновление не возьмёт. Ключ уже
создан и лежит вне проекта, в `~/.tauri/game-launcher.key` на этой машине. В
репозиторий он попасть не должен: с приватным ключом кто угодно подпишет что
угодно и это поставится игрокам. Публичная половина вписана в
`src-tauri/tauri.conf.json`.

```bash
TAURI_SIGNING_PRIVATE_KEY_PATH=~/.tauri/game-launcher.key npm run tauri build
```

В `src-tauri/target/release/bundle/` появятся установщики, а рядом подписи с
расширением `.sig`. Их прикладывают к релизу на GitHub, а в `latest.json`
описывают, где что лежит:

```json
{
  "version": "0.2.0",
  "notes": "Что нового в этой версии",
  "pub_date": "2026-11-05T12:00:00Z",
  "platforms": {
    "linux-x86_64": {
      "signature": "содержимое файла .sig",
      "url": "https://github.com/ЛОГИН/РЕПО/releases/download/v0.2.0/game-launcher.AppImage"
    }
  }
}
```

Точные имена платформ и полей задаёт Tauri, поэтому перед первой публикацией
сверьтесь с их документацией: <https://tauri.app/plugin/updater/>.

## Как добавить игру

Проще всего кнопкой «+» рядом с надписью «Игры»: лаунчер спросит название и
предложит выбрать файл игры в системном диалоге, создаст папку, положит туда
заготовку `game.json` и откроет её. Останется скопировать в папку саму игру.

Вручную то же самое: создай папку в `games/`, положи внутрь игру и файл
`game.json` рядом с исполняемым файлом. Игра появится в списке после кнопки
«Обновить».

```json
{
  "id": "snake",
  "title": "Змейка",
  "version": "0.3.0",
  "author": "мы с друзьями",
  "description": "Классика: собираем ягоды и не врезаемся в себя.",
  "cover": "cover.png",
  "entry": { "type": "executable", "path": "snake.exe" }
}
```

Поля и другие способы запуска, включая команду и ссылку, описаны в
[`games/README.md`](games/README.md).

## Правка интерфейса без сборки Rust

Интерфейс это обычная веб-страница, её можно открыть в браузере:

```bash
npm run dev        # затем http://localhost:1420
```

Rust в браузере недоступен, поэтому лаунчер подставляет демонстрационные игры
и показывает в шапке пометку «предпросмотр». Правки в вёрстке и цветах видны
сразу, сборка Rust не нужна. Адрес `http://localhost:1420/?empty` открывает
экран, который увидит человек без игр.

Что чаще всего хочется подкрутить:

| Что меняем                                | Где                                         |
| ----------------------------------------- | ------------------------------------------- |
| Акцентный цвет кнопок и выделения          | `--accent` в `styles.css`                   |
| Цвета светлой и тёмной темы                | блоки `:root[data-theme=...]`               |
| Насколько видна обложка за текстом панели  | `opacity` у `.game-art`                     |
| Ширина панели слева                        | `--sidebar-width`                           |
| Ширина карточек новостей                   | `minmax(...)` у `.news-list`                |
| Размеры и положение окна                   | `app.windows` в `src-tauri/tauri.conf.json` |
| Публичный ключ подписи обновлений          | `plugins.updater.pubkey` в том же файле     |

Иконки взяты из набора [Feather](https://feathericons.com) под лицензией MIT и
нарисованы прямо в разметке, без внешних файлов.

## Если окно не открывается

`Error 71 (Protocol error) dispatching to Wayland display` означает
несовместимость WebKitGTK с драйвером NVIDIA. Веб-процесс не может создать
GBM-буфер, композитор рвёт соединение, программа падает.

Лаунчер определяет такую систему сам по наличию `/dev/nvidia0` и отключает
ускоренный рендеринг окна. Интерфейсу он не нужен. Вмешаться вручную можно так:

```bash
WEBKIT_DISABLE_DMABUF_RENDERER=1 npm run tauri dev   # оставить родной Wayland
GDK_BACKEND=x11 npm run tauri dev                    # крайний случай: XWayland
```

Переменная, заданная снаружи, важнее автоматики. Если она уже стоит в
окружении, лаунчер её не перезаписывает.

## Проверки

```bash
npm test                                      # тесты ядра, графику собирать не нужно
npm run build                                 # проверка типов TypeScript и сборка интерфейса
```

## Что уже работает

- Панель слева: заглушка аккаунта, список игр с версиями, настройки внизу.
- Кнопка «+»: спрашивает название, даёт выбрать файл игры, создаёт папку с
  заготовкой манифеста и открывает её.
- Удаление игры вместе с её папкой, с подтверждением и показом пути.
- Каталог игр: скачивание архивов с показом хода загрузки и распаковкой в папку
  игр. Список каталога берётся по адресу из настроек, а без сети показывается
  последняя сохранённая копия.
- Докачка: оборванная загрузка продолжается с того же места, а не с нуля.
- Обновление игр: если в каталоге версия выше установленной, на карточке
  появляется «Обновить». Старая версия живёт до последнего и удаляется только
  после того, как новая распакуется целиком.
- Обновление лаунчера с проверкой подписи и перезапуском.
- Панель игры: обложка, версия, автор, размер, теги, описание и кнопка «Играть».
- Новости лаунчера из `news.json`.
- Две темы, светлая и тёмная, и закрытие лаунчера при запуске игры.
- Поиск по названию, автору, описанию и тегам, плюс стрелки и Enter.
- Запуск игры отдельным процессом.
- Понятные сообщения, если манифест испорчен, файл игры не найден или путь из
  манифеста пытается выйти за пределы папки игры.

## Чего пока нет

- Аккаунтов: в панели слева стоит заглушка.
- Проверки, что игра действительно запустилась, и списка запущенных игр.
- Обложек с редкими расширениями: распознаются png, jpg, webp и gif.
- Автоматической проверки каталога: список обновляется по кнопке или при запуске.
